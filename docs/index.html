PlanForge

PlanForge reads a planning task written in PDDL with numeric fluents, grounds it, and searches for a sequential plan. Under A* with an admissible heuristic the plan it returns is cost-optimal. It is one binary, and every configuration described on this site is reachable from that binary.

It is developed by MRlab, the Machine Reasoning Lab at Linköping University, and it began as a Rust port of a numeric extension of Fast Downward. That lineage is described on the credits page, together with the licence terms it carries with it.

What it does

  • Input. A PDDL domain and problem pair, or a single pre-translated SAS+ file. Translation and grounding happen in process: the planner never writes SAS+ text on the way to its own search. A separate planforge-translator binary exists for when the text itself is what you want.
  • Numbers. Numeric fluents in preconditions, goals and effects; comparisons and their negations; the five PDDL assignment operators; arithmetic expressions over fluents and constants. See Supported PDDL for the exact list and for the limits.
  • Search. A* for optimal planning, greedy best-first search when a plan matters more than its cost, and a two-heuristic A* variant that orders the open list with a cheap admissible heuristic and confirms with an expensive one.
  • Heuristics. Blind, a numeric LM-cut, numeric pattern databases, CEGAR-built domain abstractions and Cartesian abstractions, combined by maximisation, the canonical combination, or saturated cost partitioning; an FF-style relaxed-plan heuristic for the non-admissible case. LP-backed heuristics (numeric potentials, post-hoc optimisation) require an optional CPLEX build.
  • Output. The plan is printed and written to sas_plan in the working directory, followed by a statistics block in the same shape Fast Downward prints.
  • Budgets. --max-time and --max-memory are enforced by the planner itself, so a task that runs out of either exits with a plain report instead of being killed from outside.

The current version is 0.1.0. The admissible paths (A* with blind, numeric LM-cut, pattern databases, and the canonical and saturated-cost-partitioning combinations of domain abstractions) are the ones the test suite pins instance by instance; preferred-operator support is not implemented.

Quick start

You need a stable Rust toolchain. The crates use edition 2024, so 1.85 or newer. Nothing else: no nightly features, no system libraries, no Python.

git clone https://github.com/mrlab-ai/PlanForge.git
cd PlanForge
cargo build --release --bin planforge

That produces target/release/planforge. The repository ships small PDDL fixtures under tests/assets/, so you can solve something immediately. This one is a numeric delivery task with two robots:

./target/release/planforge \
    --search 'astar(lmcutnumeric())' \
    tests/assets/numeric-pddl-files/delivery/domain.pddl \
    tests/assets/numeric-pddl-files/delivery/pfile1.pddl

Running a pre-translated task

When you want to translate once and search many times, translate to SAS+ first and hand the planner a single file:

./target/release/planforge-translator translate \
    tests/assets/numeric-pddl-files/delivery/domain.pddl \
    tests/assets/numeric-pddl-files/delivery/pfile1.pddl \
    --output delivery.sas

./target/release/planforge --search 'astar(lmcutnumeric())' delivery.sas

Both routes report the same 49 propositional and 12 numeric variables, expand the same 73 states and return the same cost-22 plan.
